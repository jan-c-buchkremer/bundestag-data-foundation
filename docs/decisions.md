# Decisions

One line per decision, newest last. Date, decision, reason.

- 2026-09-21 — Ingest from primary sources (bundestag.de XML/XLSX, DIP API, abgeordnetenwatch), not from an existing corpus. All corpora stop in 2023 or are PDF-derived; the XML already carries speaker ids and separated interjections. (`landscape.md` §5)
- 2026-09-21 — The Bundestag MdB ID (`MDB/ID` = `redner/@id`) is the person primary key; DIP and abgeordnetenwatch ids are attributes. It is the only id that is present in both the protocol and the master data.
- 2026-09-21 — abgeordnetenwatch `ext_id_bundestagsverwaltung` is stored only when it agrees with a name+birth-year match. Verified wrong for 56/630 WP21 members.
- 2026-09-21 — Roll-call votes come from the bundestag.de XLSX, not from abgeordnetenwatch. Official, same-day, exact sitting/vote number; abgeordnetenwatch lags and has no structured Drucksache link.
- 2026-09-21 — Drucksache metadata and authorship come from DIP; the full author list via `/aktivitaet?f.drucksache=`, because `autoren_anzeige` is capped at 4. bundestag.de Open Data has PDFs only for WP21 Drucksachen.
- 2026-09-21 — Non-MdB speakers (ministers without mandate, Bundesrat, guests) get `person` rows with `is_mdb = 0`. They have ids in the XML anyway and are interesting for the fact sheet.
- 2026-09-21 — SQLite, single file, stdlib `sqlite3`; raw files kept unchanged under `data/raw/`. Home server, weekly batch, readers only need `sqlite3`. DuckDB not needed for join-heavy small-table queries.
- 2026-09-21 — No `fraction` table; fraction is a normalised string with one shared normalisation function. A table would add a join and nothing else.
- 2026-09-21 — `speech_paragraph` and `individual_vote` inherit provenance from their parent row (same raw file); every other table carries `source_url`, `source_document_id`, `retrieved_at`. Avoids repeating three columns 630× per vote.
- 2026-09-21 — One `rede` element with several speakers is split into several `speech` rows (`<rede id>-2`, …); presidency remarks inside a `rede` become `chair` paragraphs, not speeches. Keeps the clean-text unit one speaker, one voice.
- 2026-09-21 — Personal DIP API key requested by e-mail; the public key rotates and both known ones are expired. Until it arrives, DIP code is written against recorded fixtures only.
- 2026-09-21 — Name matching looks at Wahlperiode mandate holders first and at all known persons second. Nachrücker who joined after the Stammdaten file date have no mandate row yet but may already exist as persons.
- 2026-09-21 — Raw files get a `.meta.json` sidecar (url, retrieved_at); `ingest` reads provenance from there and never from the network. Keeps the store rebuildable offline.
- 2026-09-21 — DIP author activities are stored with their `activity_type`; the co-authored query does not filter on it yet. Which activity types `f.drucksache` returns is unverified until a key is available.
- 2026-09-21 — Ruff line length 120 rather than 100. SQL and f-strings otherwise wrap into unreadable fragments.
- 2026-09-21 — abgeordnetenwatch is fetched per Wahlperiode via a fixed `PERIOD_BY_WAHLPERIODE` map ({21: 161}); raw files are named `wp21-*.json`. One explicit mapping beats deriving the WP from mandate labels.
- 2026-09-21 — DIP calls stay sequential and `ingest` re-parses every raw file each run. Parallel fetching and change detection are cheap to add later; neither can be tuned without a key or a full Wahlperiode of data.
- 2026-09-21 — The protocol parser repairs one known upstream quirk: a speaker with two ids in one attribute and doubled name elements (Svenja Schulze in 21/18, 21/24, 21/25, 21/28, 21/44–46). First id wins, doubled strings are halved. Seen in 7 of 94 WP21 files; no other merged ids exist.
- 2026-09-23 — `bdf update` derives every fetch window from `data/raw/` instead of storing a state file. The raw files already are the state; a separate file could drift from them, and a missed week is caught up automatically.
- 2026-09-23 — `update` re-reads votes and DIP 14 days back and refetches Stammdaten and abgeordnetenwatch in full each run. Late publications are common, the full refetches are one file and ~15 requests, and ingest upserts idempotently.
- 2026-09-23 — Container image runs as uid 1000 with `BDF_DATA_DIR=/data`. Matches the host user, so a bind-mounted data directory is writable from both sides without chown.
- 2026-09-27 — Authorship means the DIP activity types Antrag, Kleine Anfrage, Große Anfrage, Entschließungsantrag, Änderungsantrag, Gesetzentwurf and Frage. `f.drucksache` also returns Berichterstattung (committee rapporteurs on a Beschlussempfehlung) and Antwort (government answers); both stay in `drucksache_author` with their type, but `query drucksachen` leaves them out. Observed on the 251 Drucksachen of 6–10 July 2026, the first week fetched with the personal key.
- 2026-09-27 — `author_count` takes DIP's `autoren_anzahl` unless the fetched activities name a different number of persons; then the activities win and `ingest` lists the Drucksache. In the first real week only 21/7052 (Schriftliche Fragen: 0 vs. 148 askers) disagreed; the list shows whether other types do after the backfill.
- 2026-09-27 — DIP test fixtures are recorded responses, trimmed to four Drucksachen, instead of synthetic ones. The real data differed from the spec-based guesses in details the tests pin (originator spelling `Fraktion DIE LINKE`, the vote's Drucksache as `21/6278, 21/7009`).
- 2026-09-27 — Backfill of the whole Wahlperiode (8,220 Drucksachen, 63,920 activities): Große Anfrage (227) appeared as a ninth activity type and counts as authorship. `autoren_anzahl` disagrees with the activities only on Schriftliche Fragen (75) and Fragen (15), always as 0; the activity count stays the rule.
- 2026-09-27 — Election results come from the Bundeswahlleiterin, not abgeordnetenwatch: the official returning officer, a named open licence (dl-de/by-2-0) and a "Stand" date to cite. Two files: the elected (`btw25_gewaehlte_utf8.zip`) and results per Wahlkreis (`kerg2.csv`). abgeordnetenwatch stays the source for its own data (cross-ids, citizen questions).
- 2026-09-27 — The election files are fetched once (only if missing) by `update`: they are final and have not changed since March 2025.
- 2026-09-27 — Elected candidates are matched to MdB ids with the shared name index, then each given name in turn, then a unique WP member with the same surname part and birth year. The official file lists legal names ("Joachim-Friedrich Martin Josef Merz", "Saleh, Kassem Taher"), the Stammdaten the names in use. On the real file 629 of 630 match; every match agrees with the Stammdaten on mandate type, Wahlkreis and birth year. "Stegeman" is an alias for Albert Stegemann. Ralf Schnurrbusch (AfD) stays unmatched: he has no Stammdaten record, vote or speech in the store.
- 2026-09-27 — `constituency.seat_party` is NULL where the Wahlkreis winner got no seat (23 Wahlkreise in 2025, no Zweitstimmendeckung). A list member's own first-vote share is not copied into `election_candidacy`; it is the party's Erststimme row in `constituency_result`. The two files agree on every constituency winner's share.
- 2026-09-28 — DIP list records (Drucksachen, Vorgangspositionen) are deduplicated by DIP id across range files before ingest, the most recently retrieved copy winning. `update`'s 14-day lookback makes consecutive range files overlap; counted twice, one Namentliche Abstimmung became two decisions for one vote and vote 21/96/1 lost its link after the first daily run on top of the backfill.
- 2026-09-28 — abgeordnetenwatch profile statistics go into `aw_profile` (profile URL, citizen questions, answered), one row per politician with provenance `aw politician <id>`. The counts are the profile's lifetime totals (`statistic_questions`), not per Wahlperiode; consumers must say so. Kept out of `person` so the Stammdaten upsert and the aw figures do not overwrite each other.
- 2026-09-28 — Interjections are parsed from the protocol's comment paragraphs into `interjection`, one row per actor of each part. Parts split at " – " only where a recognised part starts, because the quoted words contain dashes too. Actors: a whole fraction, some of its members ("bei Abgeordneten der"), a named person, the house. A person named with "an den/die Abg." is the addressee, not an actor (71 cases in WP 21, all matched). On the 95 WP 21 protocols: 143,574 rows; 0.2 % of parts unclassified (mostly stage directions like "Das Mikrofon wird abgeschaltet"); 51,459 of 51,467 named persons matched, the 8 misses are typos in the protocols ("Hedi Reichinnek").
- 2026-09-28 — A person's bracketed fraction is kept as printed at the time (Jan Wenzel Schmidt [AfD] before he left the fraction), not replaced by the current membership.
- 2026-09-28 — `raw.get` retries network errors (dropped connections, timeouts) like 429/5xx, and `update` isolates each source: one that still fails is skipped for the run, the rest are fetched and ingested, exit code 1. A single "Server disconnected" from abgeordnetenwatch had aborted the whole update, so DIP was not fetched and nothing was ingested.
- 2026-09-28 — Portraits come from the card list behind bundestag.de/abgeordnete (`ajax/filterlist/de/abgeordnete/1040594-1040594`, 12 cards per page), not from the biography pages: each card already has the name, fraction, biography URL, all image renditions and the caption with the credit; the biography page adds nothing that identifies the person (no MdB id). The list is fetched in full on every run, the images (864×1152 renditions, URLs with a content hash) only when new. On 2026-09-28: 639 cards, all matched; 630/630 sitting WP 21 members have a portrait.
- 2026-09-28 — Portrait credits are stored as printed ("© " dropped) and shown with every photo; the photos are used without a per-photo licence check, as decided for the cards site.
- 2026-09-28 — Cards are matched by name with the shared index, then by surname + first given name + fraction. "Krampe, Jan" (Die Linke, born 22.10.1997) is Jan Köstering in the Stammdaten: an alias in `match.ALIASES`. Titles like "Prof. Dr.-Ing. habil." are stripped from the printed given name.
- 2026-09-28 — The government roster comes from Wikidata (P39 statements starting on or after 2025-05-06), as decided for the cards site. Two SPARQL queries: the position items under Bundesminister / Parlamentarischer Staatssekretär / beamteter Staatssekretär first, then the statements with `VALUES`; one query with a subclass path timed out. `government_role.id` is the Wikidata statement id, so a role keeps its id across runs.
- 2026-09-28 — Roster members are matched by `person.wikidata_qid`, then by full name with equal or missing birth date (non-MdB speakers from the protocols have none), then by the shared name index with birth year; a name match writes the QID onto the person. Others get a person row `Q<qid>` with `is_mdb = 0`, removed again when a later ingest matches them. On 2026-09-28: 19 persons, 14 by QID, 4 by name (Hubig, Prien, Wildberger as protocol speakers, Reiche as a former MdB), 1 new (Böhning).
- 2026-09-28 — Wikidata's roster is incomplete below the cabinet and lags reshuffles: 20 roles (1 Kanzler, 18 minister roles incl. Warken's move to the Chancellery, 1 beamteter Staatssekretär), no Parlamentarische Staatssekretäre, no Staatsminister, and not Linnemann (Gesundheit) or Bilger (Verkehr). Nothing is invented to fill it: `ingest` lists the government speakers in the protocols without a roster role (34 on 2026-09-28), so the gap is visible and can be fixed in Wikidata or with a second source later.
- 2026-09-28 — Government members without a bundestag.de portrait (non-MdB ministers) get their Wikidata P18 image as an 864 px Commons thumbnail, with "<author>, <licence>" from the Commons metadata as credit. The bundestag.de portrait wins for MdBs, so the site's photos look alike.
- 2026-09-28 — Text directly under `<tagesordnungspunkt>`, outside any `<rede>`, is kept as `agenda_item_paragraph` (kinds `chair`, `comment`, `procedural` for `T_*` lines, and `speaker`/`text` for the early-WP21 Fragestunden that print answers outside a `rede`). That is where the presidency calls items, puts questions to the vote and reads out results; the printed name lists of roll-call votes (`AL_Namen`, `AL_Partei`, `AL_Ja-Nein-Enth`) are left out because the XLSX has them per member. Chair text inside a `rede` holds no decisions: over all 95 WP21 protocols only four result-like sentences stand there, all about Zwischenfragen; the parser reads it anyway.
- 2026-09-28 — Decisions on substance are extracted by rules from the chair text (`bdf/parse_decisions.py`), not by a model: the phrasing is formulaic, and a rule that misses fails visibly in the skip report. A unit ends at a result sentence ("… ist damit angenommen"); it is a show-of-hands decision when a vote question ("Wer stimmt dafür?", "… um das Handzeichen", "Gegenprobe") or a "mit den Stimmen …" clause precedes it. Fraction positions come from the answers to the questions and from "mit den Stimmen der X gegen die Stimmen der Y bei Enthaltung der Z / bei Zustimmung / bei Ablehnung"; the first position found for a fraction wins, so a closing summary cannot overwrite it. "Koalitionsfraktionen", "Opposition", "alle übrigen", "Rest des Hauses", "das gesamte Haus" and "einstimmig" resolve against the WP21 fractions (`HOUSE`, `COALITION`). Names go through `normalize_fraction`.
- 2026-09-28 — Procedure is not a decision: Überweisung and disputed Federführung, Aufsetzung/Absetzung, Tagesordnung, Zurückverweisung, Fristverkürzung, Herbeirufung, Zwischenfragen, and elections (secret or by ballot card; "gewählt"). Wahlvorschläge decided by show of hands are kept: they are decisions on a Drucksache. A change of the Geschäftsordnung by Antrag is kept too.
- 2026-09-28 — A roll-call decision is the vote's opening ("Ich eröffne die namentliche Abstimmung über …"), paired with the result read out later (often under another agenda item, sometimes the next sitting day) in order, a shared Drucksache first. Its row has the id of the `roll_call_vote` it matches: announced yes/no within 25 of the XLSX totals (the announcement is provisional), else a shared Drucksache, else the remaining ones in order; without a match the id is `<sitting>/n<k>`. Show-of-hands ids are `<sitting>/h<n>`. Where the protocol does not read the result out (the last vote of a day), `result` is the simple majority of the XLSX totals.
- 2026-09-28 — A decision's agenda item is not always the one whose text it stands in: the chair votes on TOP 22 during the debate of ZP 18. Order of evidence: an explicit "Ich komme zurück zum Tagesordnungspunkt 22a" / "Zusatzpunkt 9." in the unit, a Drucksache on an agenda item's list, the agenda item of the previous decision in the same stretch of text, the current one. `roll_call_vote.agenda_item_id` is the agenda item of the same sitting listing one of the vote's (DIP) Drucksachen, else that of its decision row. The column is added with `ALTER TABLE` to existing stores.
- 2026-09-28 — Quality gate, sitting week 6–10 July 2026 (21/88–90), every result sentence of the chair text compared by hand with the parser output: 108 decisions on substance in the protocol (98 by show of hands, 10 roll-call), 108 found, no false positives (recall and precision 100 %); all 10 roll-call decisions linked to the right `roll_call_vote` and agenda item; results correct in 108/108; fraction positions compared by hand for 70 of the 98 show-of-hands decisions (every distinct phrasing of the week), no error. Weak spots: 23 of 98 show-of-hands decisions have no Drucksache (the 23 Sammelübersichten of petitions, which name none), and 36 subjects are a bare noun ("Beschlussempfehlung", "Gesetzentwurf – zweite Beratung", "Wahlvorschläge") where the chair names no title in the vote itself; consumers should show them with the agenda item title and the Drucksache. Whole Wahlperiode (95 protocols): 1,011 show-of-hands and 65 roll-call decisions; 62 of the 67 `roll_call_vote` rows of sittings with a protocol linked (21/14/4, 21/40/7–8, 21/83/4: the vote is not in that protocol's text, 21/40's XML ends before the results; 21/47/2 same); 3 roll-call decisions (21/18, 21/60, 21/67) have no XLSX in the vote list. 33 show-of-hands decisions carry no fraction positions ("Wer stimmt dafür? – Wer stimmt dagegen? – … angenommen" with no names said). Skipped result sentences: 64 procedural, 18 election results, 9 without a vote question (repeated results such as "Der Wahlvorschlag ist damit angenommen; das noch mal zur Sicherheit", and 21/31, 21/74 where the question stands before an earlier result), 2 conditional ("Wenn das nicht der Fall ist, dann ist die Beschlussempfehlung angenommen", 21/87, a real decision that is missed).
- 2026-09-28 — The government roster is filled from all three sources at hand, each row recording its source in `government_role.source_kind` (wikidata | stammdaten | protocol): Wikidata lacks the Parlamentarische Staatssekretäre, the Staatsminister and the September 2026 reshuffle, the Stammdaten (file of 2026-04-29) have exact dates for MdB office holders but not the reshuffle, and the protocols print every speaker's office. One row per person + kind + department; dates and provenance from Wikidata, else the Stammdaten, else the protocols. Protocol dates are the first and last sitting that prints the role: evidence, not appointment dates, and to be shown as such ("belegt ab … (Plenarprotokoll)"). Rows not from Wikidata get the stable id `<source_kind>:<person_id>:<kind>:<department key>`. `source_kind` is added with `ALTER TABLE` (existing rows: wikidata); `wikidata_qid` is no longer NOT NULL, so the table is rebuilt once with its rows.
- 2026-09-28 — When the protocols show a different person as Kanzler or Bundesminister of a department after an open Wikidata or Stammdaten role of that department, the older role is closed the day before the new holder's first appearance, and `ingest` prints the inference. On 2026-09-28 one inference: Patrick Schnieder, Bundesminister für Verkehr (Wikidata, from 2025-05-06, no end), closed 2026-09-07, because Steffen Bilger speaks as Bundesminister für Verkehr from 2026-09-08 (BT-PlPr. 21/91). Warken's Gesundheit role needs none (Wikidata ends it 2026-07-29); Linnemann gets a protocol row from 2026-09-08. For "held on a day", a protocol row counts after its last evidence until contradicted (a later role of the person, a later holder of the same Kanzler/minister office), so the current cabinet includes Linnemann and Bilger.

- 2026-09-28 — Protocol-only government roles stay current after their last sitting (no automatic end), but those not printed for more than 90 days before the newest sitting are reported as stale: `bdf query stale-roles`, and a warning in the `bdf update` summary that does not fail the run (exit code unchanged). For `source_kind = 'protocol'`, `to_date` means "last seen in a protocol", not end of office. An automatic cut-off would end roles of members who simply do not speak for months (Staatsminister, Parl. Staatssekretäre speak rarely), which is worse than a role kept too long and flagged; a failing exit code would page for something only a source update can fix. On the dev store (newest sitting 2026-09-23) one role is stale: Wolfram Weimer, Staatsminister beim Bundeskanzler, last seen 2026-05-07 (139 days).
- 2026-09-29 — `bdf export` publishes the whole store as gzipped CSV per table plus a Frictionless data package, not SQLite or Parquet: CSV opens everywhere (spreadsheet, R, pandas), the data package adds types, keys and per-table licences, and gzip keeps the full Wahlperiode at ~37 MB. All tables go out: everything in them comes from public sources (the Stammdaten fields are those the Bundestag publishes; religion and family status are not stored). Only `person_photo.local_path` is left out. Field descriptions are parsed from the schema comments rather than kept in a second list that could drift. Attribution texts per source are in `export.SOURCES`, summarised from `docs/licences.md`; the portraits are exported as URL + credit only.

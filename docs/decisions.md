# Decisions

One line per decision, newest last. Date, decision, reason.

- 2026-09-21 — Ingest from primary sources (bundestag.de XML/XLSX, DIP API, abgeordnetenwatch), not from an existing corpus. All corpora stop in 2023 or are PDF-derived; the XML already carries speaker ids and separated interjections. (`landscape.md` §5)
- 2026-09-21 — The Bundestag MdB ID (`MDB/ID` = `redner/@id`) is the person primary key; DIP and abgeordnetenwatch ids are attributes. It is the only id that is present in both the protocol and the master data.
- 2026-09-21 — abgeordnetenwatch `ext_id_bundestagsverwaltung` is stored only when it agrees with a name+birth-year match. Verified wrong for 56/630 WP21 members.
- 2026-09-21 — Roll-call votes come from the bundestag.de XLSX, not from abgeordnetenwatch. Official, same-day, exact sitting/vote number; abgeordnetenwatch lags and has no structured Drucksache link.
- 2026-09-21 — Drucksache metadata and authorship come from DIP; the full author list via `/aktivitaet?f.drucksache=`, because `autoren_anzeige` is capped at 4. bundestag.de Open Data has PDFs only for WP21 Drucksachen.
- 2026-09-21 — Non-MdB speakers (ministers without mandate, Bundesrat, guests) get `person` rows with `is_mdb = 0`. They have ids in the XML anyway and are interesting for the fact sheet.
- 2026-09-21 — SQLite, single file, stdlib `sqlite3`; raw files kept unchanged under `data/raw/`. Home server, weekly batch, readers only need `sqlite3`. DuckDB not needed for join-heavy small-table queries.
- 2026-09-21 — No `fraction` table; fraction is a normalised string with one shared normalisation function. A table would add a join and nothing else.
- 2026-09-21 — `speech_paragraph` and `individual_vote` inherit provenance from their parent row (same raw file); every other table carries `source_url`, `source_document_id`, `retrieved_at`. Avoids repeating three columns 630× per vote.
- 2026-09-21 — One `rede` element with several speakers is split into several `speech` rows (`<rede id>-2`, …); presidency remarks inside a `rede` become `chair` paragraphs, not speeches. Keeps the clean-text unit one speaker, one voice.
- 2026-09-21 — Personal DIP API key requested by e-mail; the public key rotates and both known ones are expired. Until it arrives, DIP code is written against recorded fixtures only.
- 2026-09-21 — Name matching looks at Wahlperiode mandate holders first and at all known persons second. Nachrücker who joined after the Stammdaten file date have no mandate row yet but may already exist as persons.
- 2026-09-21 — Raw files get a `.meta.json` sidecar (url, retrieved_at); `ingest` reads provenance from there and never from the network. Keeps the store rebuildable offline.
- 2026-09-21 — DIP author activities are stored with their `activity_type`; the co-authored query does not filter on it yet. Which activity types `f.drucksache` returns is unverified until a key is available.
- 2026-09-21 — Ruff line length 120 rather than 100. SQL and f-strings otherwise wrap into unreadable fragments.
- 2026-09-21 — abgeordnetenwatch is fetched per Wahlperiode via a fixed `PERIOD_BY_WAHLPERIODE` map ({21: 161}); raw files are named `wp21-*.json`. One explicit mapping beats deriving the WP from mandate labels.
- 2026-09-21 — DIP calls stay sequential and `ingest` re-parses every raw file each run. Parallel fetching and change detection are cheap to add later; neither can be tuned without a key or a full Wahlperiode of data.
- 2026-09-21 — The protocol parser repairs one known upstream quirk: a speaker with two ids in one attribute and doubled name elements (Svenja Schulze in 21/18, 21/24, 21/25, 21/28, 21/44–46). First id wins, doubled strings are halved. Seen in 7 of 94 WP21 files; no other merged ids exist.
- 2026-09-23 — `bdf update` derives every fetch window from `data/raw/` instead of storing a state file. The raw files already are the state; a separate file could drift from them, and a missed week is caught up automatically.
- 2026-09-23 — `update` re-reads votes and DIP 14 days back and refetches Stammdaten and abgeordnetenwatch in full each run. Late publications are common, the full refetches are one file and ~15 requests, and ingest upserts idempotently.
- 2026-09-23 — Container image runs as uid 1000 with `BDF_DATA_DIR=/data`. Matches the host user, so a bind-mounted data directory is writable from both sides without chown.

- 2026-09-28 — Text directly under `<tagesordnungspunkt>`, outside any `<rede>`, is kept as `agenda_item_paragraph` (kinds `chair`, `comment`, `procedural` for `T_*` lines). That is where the presidency calls items, puts questions to the vote and reads out results; the printed name lists of roll-call votes (`AL_Namen`, `AL_Partei`, `AL_Ja-Nein-Enth`) are left out because the XLSX has them per member. Chair text inside a `rede` holds no decisions: over all 95 WP21 protocols only four result-like sentences stand there, all about Zwischenfragen; the parser reads it anyway. (Corrected 2026-09-29: this entry originally said the redner paragraphs printed outside a `rede` were "early-WP21 Fragestunden" and kept as `agenda_item_paragraph` kinds `speaker`/`text`. That was wrong on both counts: it is every WP21 Fragestunde (25 agenda items), and they are now `speech` rows, see below.)
- 2026-09-28 — Decisions on substance are extracted by rules from the chair text (`bdf/parse_decisions.py`), not by a model: the phrasing is formulaic, and a rule that misses fails visibly in the skip report. A unit ends at a result sentence ("… ist damit angenommen"); it is a show-of-hands decision when a vote question ("Wer stimmt dafür?", "… um das Handzeichen", "Gegenprobe") or a "mit den Stimmen …" clause precedes it. Fraction positions come from the answers to the questions and from "mit den Stimmen der X gegen die Stimmen der Y bei Enthaltung der Z / bei Zustimmung / bei Ablehnung"; the first position found for a fraction wins, so a closing summary cannot overwrite it. "Koalitionsfraktionen", "Opposition", "alle übrigen", "Rest des Hauses", "das gesamte Haus" and "einstimmig" resolve against the WP21 fractions (`HOUSE`, `COALITION`). Names go through `normalize_fraction`.
- 2026-09-28 — Procedure is not a decision: Überweisung and disputed Federführung, Aufsetzung/Absetzung, Tagesordnung, Zurückverweisung, Fristverkürzung, Herbeirufung, Zwischenfragen, and elections (secret or by ballot card; "gewählt"). Wahlvorschläge decided by show of hands are kept: they are decisions on a Drucksache. A change of the Geschäftsordnung by Antrag is kept too.
- 2026-09-28 — A roll-call decision is the vote's opening ("Ich eröffne die namentliche Abstimmung über …"), paired with the result read out later (often under another agenda item, sometimes the next sitting day) in order, a shared Drucksache first. Its row has the id of the `roll_call_vote` it matches: announced yes/no within 25 of the XLSX totals (the announcement is provisional), else a shared Drucksache, else the remaining ones in order; without a match the id is `<sitting>/n<k>`. Show-of-hands ids are `<sitting>/h<n>`. Where the protocol does not read the result out (the last vote of a day), `result` is the simple majority of the XLSX totals.
- 2026-09-28 — A decision's agenda item is not always the one whose text it stands in: the chair votes on TOP 22 during the debate of ZP 18. Order of evidence: an explicit "Ich komme zurück zum Tagesordnungspunkt 22a" / "Zusatzpunkt 9." in the unit, a Drucksache on an agenda item's list, the agenda item of the previous decision in the same stretch of text, the current one. `roll_call_vote.agenda_item_id` is the agenda item of the same sitting listing one of the vote's (DIP) Drucksachen, else that of its decision row. The column is added with `ALTER TABLE` to existing stores.
- 2026-09-28 — Quality gate, sitting week 6–10 July 2026 (21/88–90), every result sentence of the chair text compared by hand with the parser output: 108 decisions on substance in the protocol (98 by show of hands, 10 roll-call), 108 found, no false positives (recall and precision 100 %); all 10 roll-call decisions linked to the right `roll_call_vote` and agenda item; results correct in 108/108; fraction positions compared by hand for 70 of the 98 show-of-hands decisions (every distinct phrasing of the week), no error. Weak spots: 23 of 98 show-of-hands decisions have no Drucksache (the 23 Sammelübersichten of petitions, which name none), and 36 subjects are a bare noun ("Beschlussempfehlung", "Gesetzentwurf – zweite Beratung", "Wahlvorschläge") where the chair names no title in the vote itself; consumers should show them with the agenda item title and the Drucksache. Whole Wahlperiode (95 protocols): 1,011 show-of-hands and 65 roll-call decisions; 62 of the 67 `roll_call_vote` rows of sittings with a protocol linked (21/14/4, 21/40/7–8, 21/83/4: the vote is not in that protocol's text, 21/40's XML ends before the results; 21/47/2 same); 3 roll-call decisions (21/18, 21/60, 21/67) have no XLSX in the vote list. 33 show-of-hands decisions carry no fraction positions ("Wer stimmt dafür? – Wer stimmt dagegen? – … angenommen" with no names said). Skipped result sentences: 64 procedural, 18 election results, 9 without a vote question (repeated results such as "Der Wahlvorschlag ist damit angenommen; das noch mal zur Sicherheit", and 21/31, 21/74 where the question stands before an earlier result), 2 conditional ("Wenn das nicht der Fall ist, dann ist die Beschlussempfehlung angenommen", 21/87, a real decision that is missed).

- 2026-09-28 — Protocol-only government roles stay current after their last sitting (no automatic end), but those not printed for more than 90 days before the newest sitting are reported as stale: `bdf query stale-roles`, and a warning in the `bdf update` summary that does not fail the run (exit code unchanged). - 2026-09-29 — `bdf export` publishes the whole store as gzipped CSV per table plus a Frictionless data package, not SQLite or Parquet: CSV opens everywhere (spreadsheet, R, pandas), the data package adds types, keys and per-table licences, and gzip keeps the full Wahlperiode at ~37 MB. All tables go out: everything in them comes from public sources (the Stammdaten fields are those the Bundestag publishes; religion and family status are not stored). Only `person_photo.local_path` is left out. Field descriptions are parsed from the schema comments rather than kept in a second list that could drift. Attribution texts per source are in `export.SOURCES`, summarised from `docs/licences.md`; the portraits are exported as URL + credit only.
- 2026-09-29 — Nebentätigkeiten (side jobs) are stored as `side_job`, one row per abgeordnetenwatch sidejob record, filtered by mandates of the Wahlperiode (`/sidejobs?mandates[entity.parliament_period]=`), paginated at the 30 requests/minute rate limit. `ingest_side_jobs` deletes and re-inserts a Wahlperiode's rows on every run, so a withdrawn entry disappears rather than lingering. `person_id` is set via the aw mandate → politician → person mapping already in the store (`wp21-mandates.json`, `aw_profile`), not by new name matching. Fields are the published facts only (organisation, category, Stufe/range, interval, dates, topics); decided with Jan: no linking of a member's declared income to their speeches or votes, no ranking of members by income, no summing income across members — the site shows sourced facts, not a derived score. abgeordnetenwatch's category and Stufe codes are its own numbering of the Bundestag's Verhaltensregeln (Anlage 1 GO-BT) categories and income bands; the underlying obligation to disclose is the Bundestag's "Veröffentlichungspflichtige Angaben", abgeordnetenwatch only republishes it (CC0 1.0, `docs/licences.md`). On a live fetch (2026-09-29): 4,628 side jobs, 3,050 matched to a person. The unmatched third are mostly (1,564) old entries whose `mandates[0]` still points at a candidacy/mandate record of a previous Wahlperiode (2013–2025) that abgeordnetenwatch's own WP21 collection endpoints no longer list (its `type=mandate` listing only returns currently-held mandates; a member who left mid-term, e.g. Andreas Jung, replaced 2026-05-18, drops out even though the mandate record itself still says `parliament_period` 161) — resolving those would need one API request per stale mandate id (~500), which is out of scope for facts already carried by the still-current mapping.
- 2026-09-29 — Every WP21 Fragestunde (25 agenda items, all titled "Fragestunde") prints its questions, answers and Nachfragen as `<p klasse="redner">` paragraphs directly under `<tagesordnungspunkt>`, not inside a `<rede>`; a prior entry above wrongly called this "early WP21" and let the text land as plain `agenda_item_paragraph` rows with no `person_id`. `parse_protocol._is_fragestunde` now detects such an item structurally (no `<rede>` at all, at least one direct-child redner paragraph, so it is not tied to the German title), and `_split_fragestunde` turns each run starting at a redner paragraph into a `speech` row of the new `kind = 'fragestunde'` (id `"<agenda_item_id>/f<n>"`, synthetic and stable across re-parses), attributed to its speaker via the same `_speaker()` as a normal `<rede>`; `<kommentar>` attaches to it and earns `interjection` rows exactly as inside a `<rede>`. They are shown like any other speech but excluded from speech counts and speaking shares (cards repo), because a Fragestunde turn is not a debate contribution. Recording the question number ("Frage 7") and the addressed ministry as their own fields was skipped as not cheap enough to be worth it: `speech.fraction` (the asker's party) and `speech.speaker_role` (the answering office, already parsed from `rolle_lang` the same way as any other speaker) already give callers what they need (questions per fraction, answering ministries/Staatssekretäre). The presidency's framing text ("Ich rufe die Frage 1 … auf", "Herr Staatssekretär.", "Haben Sie eine Nachfrage?") stays `agenda_item_paragraph` (`chair`), as before; `speaker`/`text` no longer occur as `agenda_item_paragraph` kinds. On the dev store (WP21): 25 Fragestunde items, ~1,474 `fragestunde` speeches. A store from before this change needs one `bdf ingest` (or the next `bdf update`) after deploy: `ingest_protocols` already reparses and replaces every sitting's speeches wholesale on every run, so no separate migration or parser-version bump is needed, only the column added by `db._ADDED_COLUMNS`.
- 2026-09-29 — DIP Vorgangspositionen are stored as `vorgang_position`, one row per position, from the range files already fetched for vote linking (no new requests; the next `ingest` fills it). `vorgang_id` has no foreign key: `vorgang` only holds Vorgänge reached through a fetched Drucksache, and 376 of 17,918 Vorgänge with positions are not among them. - 2026-09-29 — The Wahlkreiseinteilung BTW 2025 by Gemeinde is stored as `constituency_municipality` from the Bundeswahlleiterin's `btw25_wkr_gemeinden_20241130_utf8.csv` (Gebietsstand 2024-11-30, dl-de/by-2.0), fetched with the other Wahl files. - 2026-09-30 — Block items are split into `agenda_sub_item` rows (see `docs/design.md`), additively: `agenda_item` rows, ids and titles stay as they were. A sub-item starts at a chair paragraph that is only a call-up ("Tagesordnungspunkt 41c:", "Zusatzpunkt 10a:", "Wir kommen zu Tagesordnungspunkt 12k:") and needs a second distinct call-up in the same item; a repeated label continues the same sub-item. Not split: "Tagesordnungspunkte 7a und 7b" debated together, call-ups followed by words ("Tagesordnungspunkt 7a: Wir kommen zur Abstimmung über …", the votes of a debated pair) and the "40 a) / b)" lists of Überweisungen im vereinfachten Verfahren, because no call-up separates their parts and the titles of debated parts are one list. Consequence: an item like 21/96/5 (Überweisungen 40a-40y, ZP 2a-2d) gets sub-items only for the two individually called up ones (40p, ZP2a), and 21/18/4 for ZP2f and ZP2g. Labels of Zusatzpunkte are prefixed "ZP" so 6a and ZP6a differ. Zusatzpunkte 1 and 2 of 21/42/6 (Einsprüche) become sub-items ZP1..ZP4 too: the rule is the call-up, not the block wording.

- 2026-09-30 — A vote can end without "angenommen"/"abgelehnt": "Dann ist das einstimmig so beschlossen" (21/50/7, 37b), "Damit ist die Kenntnisnahme einstimmig beschlossen" (21/25), "Dann ist auch dies so beschlossen worden" (21/14, 37g). - 2026-09-30 — `speech.sub_item_id`: a speech in a block item is attached to the sub-item during which it was given, e.g. Corinna Rüffer's ergänzende Berichterstattung (ID219606600) stands after the call-up of 41l in 21/96/6 and gets `21/96/6/41l`. A speech has no paragraph position of its own, but every `agenda_item_paragraph` knows how many speeches of the sitting precede it (`after_speeches`); speech `position` p stands after the last paragraph of its item with `after_speeches < p`, and the sub-item whose `first_paragraph`..`last_paragraph` contains that paragraph is the speech's. So a sub-item spans the speeches between its call-up and the next one, including the chair's vote after them. NULL for speeches in items without sub-items and for a speech before the item's first call-up (none in the data). A speech that follows another with no agenda paragraph between (a speaker change inside one `<rede>`) takes the same sub-item; a call-up spoken inside a `<rede>` is not seen, since call-ups are only recognised among the chair paragraphs directly under the item. Set by the protocol ingest, which rewrites the speeches wholesale, so a re-ingest is idempotent and a store built before the column migrates (`_ADDED_COLUMNS`, index `speech_sub_item`) and fills it on the next `bdf ingest`. Result on a copy of the dev store plus protocols 21/96-97 (14,847 speeches): 11 speeches in 8 block items get a sub-item, none in a block item is left NULL; only one is not anchored by a chair call-up directly before it (ID211406900 in 21/14/6, second speaker of the same debate as the previous one, both under 37b).
